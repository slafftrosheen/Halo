# Everyday tools

Status: implemented and integrated; final verification is tracked in IMPLEMENTATION-LEDGER.md. Source implementation does not establish phone or participant acceptance. The current GitHub issue was reread on 2 November 2026 and is unchanged from ISSUE-63-SOURCE.md (updated 2026-11-01T17:12:43Z).

`EverydayToolContracts` publishes strict nested schemas; `EverydayToolExecutor` adapts them to the existing Runtime `ToolExecutor`. `HostTools` registers that executor in the phone composition root. `HaloToolDescriptors` supplies capabilities, replay and approval policy. The built-in `halo.everyday` skill supplies discovery. This adds no agent, parser of conversational text, alternate database or independent network client.

The tools query/create/edit organizer records, recurrence exceptions and delivery receipts; read/search/edit/reorder world clocks; inspect/save/manage/preview/refresh sources; build/read/stop/configure daily briefs; navigate exact canonical instruments; and query/configure/request launcher widgets. Screen's existing preview/apply tool gains typed per-card configuration at an exact layout revision and index. Native widget writes require the exact installed ID and configuration version. Android remains responsible for accepting a placement request.

Queries return bounded records and exact versions. Organizer search returns titles and date metadata, while get reads one identified record. Source lists omit bodies; source get reads an identified selected/enabled/unmuted source, optionally one identified article. Brief reads revalidate current source selection and child grants. Stored feed text and labels are untrusted facts, never tool instructions. Direct executor calls validate the same strict schemas used for discovery.

Writes use the canonical repository CAS and the current foreground/family/mode authority. Uncertain writes are never replayable; callers must query current state. Local edits do not grant notification/exact-alarm access or assert delivery. The delivery receipt is the authority for Android scheduling precision. Read-aloud returns a playback request, not an audible/completed claim; navigation and widget placement likewise distinguish dispatch from acceptance.

Source saving never fetches. Refresh and URL preview use `CollectorCoordinator`/`CollectorPreview`, their persistent quotas, and the shared revocable `RemoteDispatchPolicy`. A Local-mode refresh keeps the cache and reports the actual `LOCAL_ONLY` attempt. A brief build reads local snapshots and has no model or fetch dependency. Kids can read explicitly shared records/approved selected external sources and build/read a filtered brief; adult mutations and adult clock configuration are unavailable.

Everyday tool identities are classified in `PersonalConfigurationToolAccess`, so tool discovery/results inherit the existing Workspace disclosure boundary and result provenance. Selected weather/clock context is location data; briefs and internal source facts can include activity/device categories. Neither global Power nor an ordinary tool approval expands a disabled context category. The provider receives only the invoked tool's bounded result; the new adapters do not append the full database to prompts.

Portable archive/restore, optional first-run setup, Library references, Activity/Timeline links and EN/RU/LV/PL labels are integrated. See EVERYDAY-INTEGRATION.md and LOCAL-POWER-MATRIX.md for actual owners, recovery and disclosure. Final evidence and APK installation are tracked in the ledger. Participant and real-phone acceptance remain separate.
