# Network ownership audit

Status: the initial inventory below is retained as an audit snapshot. The governed-download batch is implemented and host verified as recorded below; the full Local-mode matrix remains open.

The two serialized `PrivacyMode` values (`PRIVATE`, `CLOUD`) are compatibility identifiers. The issue requires user-facing Local and Power. Keep one durable global choice and revocable revision authority. Source selection, model readiness, OS permissions, account authentication and parental capability restrictions are separate concerns, not extra privacy modes.

Required matrix: Local and Power across Home, Screen, Workspace, Kids, Study, voice, Android widgets, collectors and model-download workers. Measure outgoing calls with fake transport/loopback fixtures; Local must make zero external calls, including DNS/preview/provider checks. Changing mode/profile/parent authority revokes admitted work. Switching back to Power must not revive a stale request or reuse private-context authority. The UI must not present an unavailable model as a third global mode.

The audit also found the existing profile provider registry can initialize providers when checking configured destinations. Public collector/model-download permission must avoid a recursive provider-construction dependency. Reuse policy ownership while separating shipped transport IDs from credential-provider enumeration.

## Governed-download checkpoint — 1 November 2026
