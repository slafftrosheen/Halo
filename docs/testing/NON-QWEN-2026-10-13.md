## Evidence-driven fix

Both Halo provider verification and raw probes previously used only eight output tokens. Reasoning tokens consume that budget, even when the artifact does not advertise switchable native thinking. The LFM Thinking converter documents its separate thought channel and the risk of truncating before the final answer: [model publisher documentation](https://huggingface.co/litert-community/LFM2.5-1.2B-Thinking).

Verification and diagnostic output budgets are now bounded at 256 tokens, retaining the existing 120-second generation deadline. Reasoning alone still cannot pass: a visible answer is required. Raw failure diagnostics now report the reasoning character count and output budget without recording reasoning content.

The phone matrix now checks device availability before each run and distinguishes `NOT_RUN_DEVICE_UNAVAILABLE` and `RUNNER_INTERRUPTED` from completed failing instrumentation. Incomplete runs still make the matrix fail. A disconnected-device run confirmed the new status and failure behavior.

The changed LiteRT module passed all 164 unit tests. Both updated APKs built successfully in 5m16s. The earlier native-intent/language/runtime focused build passed 410 tests with zero failures/errors. The fixed APK source stamp is `83f6600be89a+dirty`; file hashes are recorded in `fixed-build.json`.

After repeated connection loss, ADB reconnect and a complete ADB server restart still detected no device. The user requested another retry; that retry also found no device. The updated APKs have therefore not yet been installed, and no physical acceptance is claimed for the verification-budget change.
