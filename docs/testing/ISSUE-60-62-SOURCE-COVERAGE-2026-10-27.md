## Concrete residual source changes

- `app/src/main/java/com/halo/app/screen/HaloScreen.kt`: calendar reads now distinguish loading, a successfully empty calendar and provider failure. A null provider cursor cannot claim “nothing scheduled.” Successful reads carry their actual read timestamp. Recheck permission before and after the read; clear private calendar data and cancel the coroutine when privacy masking applies. Publish state only on returning from IO to the active effect, preserving cancellation. Calendar loading copy is supplied in `app/src/main/res/values{,-ru,-lv,-pl}/screen_source_state.xml`.
- `app/src/main/java/com/halo/app/screen/ScreenWorkspaceGrid.kt`: long-lived drag handlers use current move/resize callbacks and geometry, and restart when column count changes. This prevents a same-shaped grid from retaining an obsolete draft/list callback. Keyboard and TalkBack actions use the same current bounded edit callbacks. Existing 48dp controls and explicit card options remain.
- `HaloScreen.kt`: ambient and reduced-motion cards suppress transient update flashes and update Lottie decoration. Real text/status/timestamps still update; the existing periodic burn-in position shift is retained.
