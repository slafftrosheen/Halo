## Prioritized remaining findings

1. **P2 — Studio recovery is too generic.** Ordinary edit/save/import/export failures become one Boolean and one reopen/reselect message. A person cannot reliably tell which operation failed or which recovery fits. Preserve the operation/reason and offer a matching retry/reselect/reopen action while retaining the draft. Evidence: [StudioViewModel](C:/Users/slavd/HaloEco/Halo-zone5/app/src/main/java/com/halo/app/ui/workspace/StudioViewModel.kt:263), [editor error](C:/Users/slavd/HaloEco/Halo-zone5/app/src/main/java/com/halo/app/ui/workspace/StudioScreen.kt:218). This is a source finding, not a failure deliberately induced on the phone.
2. **P3 — Compact Studio requires lengthy scanning.** All actions is a flat list, and relocated utility plus statusLabel repeat state. The 200% landscape capture shows the cost in the first viewport. Final concise installed copy reduces the wording; command grouping and one state presentation would further reduce scanning. The operations remain reachable, so this is not a task blockage.
3. **P3 — The inline orb has no visible action caption.** Talk is correctly exposed to accessibility, while a first-time sighted user must infer the ring's voice role. Menu and All actions are explicitly named. A future visible state caption could improve first-use recognition; no gesture-surface change is required for this review.

Library's horizontal filters/collections show partial next items at the edge, and long file names truncate or wrap. These are workable disclosure patterns, with additional scanning rather than evidence of lost content.
