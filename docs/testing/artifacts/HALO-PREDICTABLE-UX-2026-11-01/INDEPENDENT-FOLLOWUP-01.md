## Actionable findings

Paths are relative to `app/src/main/java/com/halo/app/` unless stated otherwise. Findings are source-backed failure scenarios, not claims of observed physical-device data loss.

| ID | Priority | Finding, trigger and correction |
|---|---|---|
| F01 | **P1** | **A failed Notes draft can be overwritten by a stored observation.** `ui/screens/notebook/NoteEditorViewModel.kt:293–305` only protects `SAVING`/`CONFLICT`. The new recovery-write error path at `:1106–1110` sets `FAILED`; a subsequent document observation runs `publishBlocks`, replaces local text/blocks and reports `SAVED`. Trigger: structured edit → fail recovery/commit → external rename/edit emits a snapshot. Protect unsaved local/source ownership independently of display status. Add a document-backed VM test for this sequence. |
| F02 | **P1** | **Back accepts an older-base conflict draft that reopening ignores.** `NoteEditorViewModel.kt:1271–1274` permits departure on `draftKept` after conflict. `data/notebook/NotebookDocumentModel.kt:192–193` rejects recovery behind the committed revision; `NoteEditorViewModel.kt:372–401` then omits the exact recovery. Trigger: keep local draft at N → concurrent writer commits N+1 → conflict → Back → reopen. A single-block note can show only stored content; the legacy multiblock fallback loses exact structure/source text. Expose the complete older-base recovery as a conflict candidate, or keep departure blocked until it is recoverably exposed. Test blocks, title and unapplied source text. |
| F03 | **P2** | **Accepted Study answer input can make the entire recovery record unreadable.** `ui/screens/study/StudyLessonStore.kt:72–74` accepts 100 answers of 1,500 characters. `:59–65` writes serialized JSON before verifying against the `:36` 200,000-character read cap. Seventy answers of 1,500 double quotes exceed that cap after escaping; the new bad record replaces the prior good one and all subsequent recovery updates fail while reading it. Bound the encoded payload before writing, or choose bounds that cover accepted escaped input; preserve the prior record on rejection. Add a quoted/unicode worst-case payload test. |
| F04 | **P2** | **Studio retry loses the original revision when classifying a stale retry.** `ui/workspace/StudioViewModel.kt:303–306` captures a block using the original revision, but `operation()` at `:290` snapshots the newer visible revision when retried. If another writer advanced the project, the old block correctly fails its owner guard, yet read-back equals the new snapshot and `:301–313` classifies it as retryable `FAILED` again. Store original id/revision with the retry admission; reject a changed revision as `CHANGED` without replay. Test failure → external revision update → Retry. The repository guard prevents an overwrite; the regression is a misleading retry loop. |
| F05 | **P2** | **Interrupted Studio outcomes are still introduced as definite failures.** `ui/workspace/StudioRecovery.kt:42–47` always prepends the operation's “Could not …” text before “result is unconfirmed.” If export/save committed before process interruption, the opening claim is unsupported. Use operation-specific interrupted wording that leaves the result unknown until read-back, rather than combining failure and uncertainty. Extend the interrupted-export test to assert the rendered wording. |
| F06 | **P2** | **Studio open/observation recovery lost its Retry control.** `StudioViewModel.kt:94,97` creates `OPEN` failures with `canRetry=false`; `StudioRecovery.kt:65` hides the button. The old screen exposed Retry. A transient observation failure stops collection and now offers only Dismiss, leaving stale/absent content. Provide a distinct re-open action for `OPEN`, clear prior mutation retry admissions, and test failing observation then restored availability. |

Commands can fit only through internal scrolling rather than the promised relocation to Actions. Measure this branch's full actual height, as with workspace menus, and test a boundary where it exceeds the quarter-height budget. |

## Improvements supported by the source

- Studio now names operations and reads the real project owner before adding retained-work wording. No blind retry of output-creating operations was introduced.
- Notes now separates recovery acknowledgement from commit state and awaits the leave gate. Source-edit recovery is represented explicitly. F01/F02 are remaining holes in that approach.
- Study card answers now use the existing recovery owner and failure copy no longer unconditionally promises saved text. F03 is a bounds/atomicity defect in the new record.
- File tools now distinguish operation, access and interrupted/cancelled outcomes. No additional concrete authorization regression was found in this bounded review.
- Orb captions map consistently to current callbacks. Compact commands retain the existing action dispatch and disabled reasons, with localized search/grouping. No concrete child allowlist or dropped-action regression was found.
- Library query/filter/sort/collection/selection now use SavedStateHandle and have focused restoration coverage. That test does not yet establish real navigation/list-anchor behavior.
