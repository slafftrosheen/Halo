## Remaining concrete blockers

| ID / priority | Trigger, evidence and correction |
|---|---|
| E01 remains / **P1** | **The UI can relabel a delayed picker result with a newer token.** `ui/workspace/WorkspaceExternalExportUi.kt:59` passes the current mutable `pickerToken`, overwritten at `:117` on each admitted launch. The session correctly rejects an old token, but this host can supply the new token for an old result. In particular, restoring an outstanding picker A changes it to a nonbusy phase (`data/workspace/WorkspaceExternalExportSession.kt:50–56`); launching B before A's late result replaces the UI token. A's destination can then be accepted as B's. Bind result registration to its actual launched attempt, or prevent replacement until the outstanding attempt is resolved. Cover the integrated host callback path, not only direct owner calls carrying a correct old token. The earlier double-activation catch problem is fixed. |
| E04 remains / **P2** | **An invalid result still strands the dialog when journal persistence also fails.** `WorkspaceExternalExportSession.kt:106–108` swallows the failure to persist FAILED. Trigger: admit PICKER, fail the next storage write, return `file://...` or an oversized URI. State remains PICKER, the host clears its token (`WorkspaceExternalExportUi.kt:60`), and Close remains disabled (`:125`). Apply a nonbusy in-memory fallback, as adjacent branches already do, while preserving any previous destination uncertainty. Verify zero output writes and recoverable controls. |
| G01 / **P2** | **Explicitly requested guidance disappears in accessible layouts or with guide lights disabled.** `ui/zone5/Zone5TaskHelp.kt:37–38` starts guidance and closes Help through `ui/presence/HaloZone5OrbLauncher.kt:278–279`. `ui/shell/HaloZone.kt:82–85` still requires `zone5GuideAllowed`, which rejects compact/large-text/narrow fallback, IME and `guideLight=false` (`ui/zone5/Zone5Guidance.kt:69–71`). At 200% text or with lights off, “Guide me one step at a time” produces no next-step presentation. Keep requested instructions available or render a static, labelled alternative independent of optional motion/cues. Do not remove the accessible layout safeguards merely to enable the animation. |
| G02 / **P2** | **Study guidance stalls after New lesson and does not finish on the saved-lesson receipt.** `ui/screens/study/StudyHomeScreen.kt:148` always supplies the incomplete `page.study.new` step; that action disappears in setup (`:155`). It overrides the valid material next step at `HaloZone.kt:78–81`, then fails the live-action match. On the saved lesson, `StudyScreen.kt:180` supplies completed IDs but no help steps; automatic exit requires a nonempty complete list (`ShellPageActions.kt:72`). Supply setup-aware steps or the eligible owner next step, and explicitly finish this guided sequence on its confirmed lesson result. |
| G03 / **P2** | **Closing a successful output reverses the Help completion state.** Studio's export step uses `state.output != null` (`ui/workspace/StudioScreen.kt:129`), but result dismissal/opening clears it (`:433–436`). Notes uses `exported != null` (`ui/screens/notebook/NoteEditorScreen.kt:221`), cleared by Done/dismiss (`:635–639`). Reopening Help asks to export again despite the confirmed output. Retain an owner/source-version completion receipt separately from result-dialog visibility, and reset when the relevant source changes. |
| G04 / **P2** | **Unavailable Help actions omit the explanation and can lead to a silent guide.** `Zone5TaskHelp.kt:33–38` renders the next button disabled without `owner.disabledActionReasons`, then offers Guide me even when no enabled action can be highlighted. For example, a saved Markdown source view can offer an unavailable export. Display the actual unavailable reason and retain a useful explanation/next step until the action is available. A missing action should describe the required current-view step rather than dismiss Help into silence. |
| G05 / **P2** | **File-tool Help describes controls that the surface does not have.** `ui/workspace/WorkspaceFileToolsScreen.kt:161` uses `zone5_help_note`. Its text (`app/src/main/res/values/strings_task_help.xml:21`) instructs writing in a note, using Add for headings/checklists/images, and applying Markdown source. A PDF/image or other file-tool selection cannot follow those instructions. Match explanation/examples to the selected supported file kind and its current Open/Create/edit/export commands. |
