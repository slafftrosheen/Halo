## Residual voice recovery defect implemented

`app/src/main/java/com/halo/app/ui/screens/home/HomeViewModel.kt`, existing `SpeechRejected` event collector:

1. Resolve the capture from `input.captureId` or the event's fallback `captureId` before altering UI state.
2. Ignore intentional cancellation, a terminal event for a different current capture, and an event bound to a conversation that is no longer active. Previously a delayed rejection from an old capture could clear the new capture's requested-listening state and replace its recovery notice.
3. For a non-recapturable rejection, end Voice Mode using the resolved capture. Previously this branch only used `input?.captureId`, so a legitimate event carrying only `captureId` could leave Voice Mode enabled without a listening/answer continuation.

This is a correction to the current Home owner, not a new voice engine, retry policy or capture grant. The existing bounded automatic recapture classification and serialized command queue remain authoritative. Genuine speech/barge-in remains unqualified for this delta.
