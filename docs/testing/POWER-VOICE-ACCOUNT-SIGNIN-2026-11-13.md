## Verified primary sources, 2026-11-13

- [OpenRouter TTS](https://openrouter.ai/docs/guides/overview/multimodal/tts): dedicated `POST /api/v1/audio/speech`, raw audio output, and model discovery using `GET /api/v1/models?output_modalities=speech`. Voice identifiers and defaults depend on the selected model. Avoid hardcoded unverified voice/model combinations; formats described are MP3 and PCM.
- [OpenAI ChatGPT plan usage](https://developers.openai.com/siwc/token-sharing-open-source): eligible open-source/local apps can request ChatGPT-plan access with OAuth dynamic registration and a persisted opaque host ID. No access to ChatGPT conversation history is implied. Paid/remote-hosted apps have a different enrollment path.
- [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference): use account-specific `/v1/models` (`models`, `visibility`, `slug`, `display_name`) and public `/v1/responses`, not ChatGPT backend endpoints. Set `store:false`, `stream:true`, consume `response.completed`; handle midstream subscription-limit failures and interrupted streams truthfully.
- [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations): history is supplied explicitly; several normal Responses parameters/tools are unsupported. Audio/video inputs, transcription and Files uploads are not supported by this grant. Do not treat this login as a TTS entitlement.
- [Hermes providers](https://hermes-agent.nousresearch.com/docs/integrations/providers): ChatGPT OAuth is documented; current Google consumer-subscription access is explicitly not documented/supported by its Gemini provider. Earlier search results for Gemini CLI login conflict with current authoritative documentation.
- [Google consumer-account deprecation](https://developers.google.com/gemini-code-assist/docs/deprecations/code-assist-individuals): consumer Gemini CLI/Code Assist login ended June 18, 2026; Google directs consumers to Antigravity. Investigate current official Antigravity integration before proposing a Google subscription implementation. Do not claim a working route based on stale Gemini CLI instructions.

Registration details were verified against the official [OpenAI devkit OAuth implementation](https://github.com/openai/sign-in-with-chatgpt-devkit/blob/0a36fefeb913055c8c7a1a29b63d82b96b2e841a/packages/local/src/oauth.ts). No tokens, passwords or subscription credentials have been read or requested in chat.

## Implementation in progress

- `PrivacyModeStore` normalizes obsolete feature cloud flags to the app-wide mode. Kids, Study and reading use that choice; source access, OS permissions, adult configuration and explicit paid-media action consent remain owned by their existing controls. Old Kids cloud and Study session-choice controls are removed. Local/Power still retains independent provider/voice preferences.
- `OpenRouterSpeechProvider` uses the existing OpenRouter key, live speech-only catalog, explicit model/voice and the dedicated speech endpoint. Qualified Gemini models request documented 24 kHz mono PCM; other models request MP3 and Android decodes the actual format. The common speech owner handles playback. `OpenRouterSpeechControl` is shared by the screen and typed tools; configuration is bound to catalog version and profile revision. Speech synthesis is billable OpenRouter usage, separate from ChatGPT subscription access.
- `ChatGptAccount` implements verified discovery, dynamic app registration, PKCE/state/nonce, RS256 identity verification, protected token storage, scope checks, refresh checkpoint recovery and local logout with separate remote-revocation outcome. `ChatGptBrowserLogin` owns a bounded loopback-only callback; passwords/MFA remain in the external browser. `ChatGptSubscriptionProvider` uses the public account catalog and Responses SSE, accepts only completed responses and retains namespaced tool-call identity. It never reads the OpenAI API key. Initial supported input is text; image/audio/video capability is not advertised.
- Google: the current [Antigravity installation documentation](https://antigravity.google/docs/install) documents consumer Google account login for App/CLI/IDE. Its programmatic SDK instructions describe API keys, Vertex and local models. Google's [current ACP clarification](https://discuss.ai.google.dev/t/conflicting-guidance-on-using-t3-code-with-personal-google-ai-subscriptions/197131/3) permits a direct interactive client to launch the official unmodified ACP runtime and use its native authentication; this is not a reusable third-party Android inference OAuth grant. [Further clarification](https://discuss.ai.google.dev/t/policy-question-omp-hosting-unmodified-antigravity-acp-for-one-user/199753/2) distinguishes direct human-driven ACP clients from wrapping that runtime as a model provider in another agent. No verified Android consumer subscription route is implemented. Existing Google Cloud authorization remains labelled as Google Cloud, not consumer subscription usage.

## Tool operability

All new contracts use ToolOperability version 1 and actual `HaloToolDescriptors`/`HostTools` registration. OpenRouter operations are `halo_openrouter_speech_status`, `halo_openrouter_speech_models`, `halo_openrouter_speech_configure`; owner is `OpenRouterSpeechControl/PrivacyModeStore`. Account operations are `halo_chatgpt_account_status`, `halo_chatgpt_account_sign_in`, `halo_chatgpt_account_disconnect`; owner is `ChatGptBrowserLogin/ChatGptAccount`. Closed arguments, bounded results, profile/catalog or account version checks and no-replay mutation policies apply. Browser sign-in reports dispatch only; local logout and remote revocation are separate. Password/MFA/provider approval is an explicit human security exception, never an assistant credential-entry operation.
