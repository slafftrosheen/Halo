## Root causes and reference evidence

- The unrestricted multi-device CDM scan does not offer the already-connected A2. Android's [AssociationRequest source](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/master/core/java/android/companion/AssociationRequest.java) documents searching bonded devices when a single-device request supplies an exact Bluetooth address. The repair offers Android's actual paired devices, takes an explicit choice, then requests CDM approval for exactly that address. Nearby discovery remains an explicit alternative. Device names never establish BLE-to-audio identity.
- CDM returns its MAC address through `MacAddress.toString()`, which uses lowercase. Bluetooth device lookup requires canonical uppercase. Approval/restoration must resolve the existing bond rather than treating an invalid lookup as an unbonded or unknown device. Brand-name fallback in system-association restoration is removed.
- The current Android file path uses a hotspot credential provider, but the active event router produces Wi-Fi Direct IP/error events rather than hotspot credentials. A fresh phone retry entered transfer mode and exited about 30 seconds later without any P2P discovery.
- The [Android reference P2P controller](https://github.com/FerSaiyan/Alternative-HeyCyan-App-and-SDK/blob/main/android/CyanBridge/app/src/main/java/com/fersaiyan/cyanbridge/ui/wifi/p2p/WifiP2pManagerSingleton.kt) was inspected on 2026-11-12 (content blob `7c49d9bee2ed8fee51f2e90c750bf7d426807817`). It uses discovery, an explicit `WifiP2pConfig` and WPS PBC. The reference MainActivity starts discovery before the existing transfer command and reads the BLE-reported address. No new BLE payload, reset command, name alias or guessed IP is introduced here.
- Android's [Wi-Fi Direct guide](https://developer.android.com/develop/connectivity/wifi/wifi-direct) distinguishes successful connection-request dispatch from an actual formed group. Halo must observe the selected peer in the group before HTTP. The [group interface](https://developer.android.com/reference/android/net/wifi/p2p/WifiP2pGroup#getInterface()) identifies the local route. Transfer uses that Network or sockets bound to that interface's observed local address, without changing process-wide routing. The phone's group-owner address is never used as the glasses' HTTP endpoint.

## Canonical owners and operation contract

Audio remains owned by `HeyCyanAudioPairingCoordinator` and `SpeechOutputRouteController`. The UI chooses an exact paired endpoint; Android retains companion approval ownership. Pairing and an available route do not prove audible output.

File list/import/cancellation remain owned by `DeviceMediaManager` through the existing `HeyCyanCaptureCoordinator` session and driver resource lease. Existing typed operations, selected device/source versions, bounded selection/size limits, original-byte hashing, staging cleanup and policy gates remain in force. The new peer choice and Android Wi-Fi permission are human/platform security prerequisites, not assistant-inferred device identity or new network privileges. The transport is available to the same shared owner used by UI and typed operations.

Existing descriptors are `halo_device_files_status`, `halo_device_files_refresh`, `halo_device_files_import` and `halo_device_files_cancel` under capability `halo.devices.files`. The peer prompt is hosted by AppShell, so operations initiated through the assistant can present the same explicit choice even outside Devices. Kids mode does not display the prompt. No new automatic pairing or file-selection capability is advertised.

Halo sends no file-deletion command to the glasses. On-device retention after a successful GET is not established: later readback found the test photo no longer served. No photo is sent to a model or remote provider. Downloads are chosen explicitly and copied through the existing Library importer. A fresh BLE IP is required for each transfer session; stale process state and ordinary Wi-Fi/default network fallbacks are rejected. Cleanup only removes the group belonging to the selected transfer peer.
