# HeyCyan Wire Format

The HeyCyan hardware protocol communicates via BLE GATT characteristic writes/notifications. The packet structure is generated by `com.oudmon.ble.base.communication.LargeDataHandler.addHeader()`.

## Frame Structure
Every frame follows a strict header + payload + CRC format, or a special 16-byte fixed-length format for legacy commands.

### LargeDataHandler Format (BC Frames)

| Offset | Length | Name | Description |
|--------|--------|------|-------------|
| 0 | 1 byte | Magic | Always `0xBC` (-68 in signed byte) |
| 1 | 1 byte | Action | Command/Action code (e.g. `0x41` for Control, `0x73` for Device Report) |
| 2 | 2 bytes | Length | Payload length (Little-Endian) |
| 4 | 2 bytes | CRC16 | CRC-16 of the Payload data only (Little-Endian) |
| 6 | N bytes | Payload | The actual command/response payload |

**Empty Payloads:** If the payload is empty (Length = 0), the CRC16 field is hardcoded to `0xFFFF` (`[-1, -1]`).

### CRC-16 Algorithm
The CRC is a standard CRC-16 (MODBUS-like) applied **only to the Payload**.
- **Polynomial**: `0xA001` (40961 in decimal, which is `0x8005` bit-reversed)
- **Initial Value**: `0xFFFF` (65535)
- **Reflect In/Out**: Yes (shifts right)
- **XOR Out**: `0x0000`

```java
// Vendor implementation
public static int calcCrc16(byte[] bufData) {
    int CRC = 65535;
    int POLYNOMIAL = 40961;
    if (bufData.length == 0) return CRC;
    for (int i = 0; i < bufData.length; ++i) {
        CRC ^= bufData[i] & 0xFF;
        for (int j = 0; j < 8; ++j) {
            if ((CRC & 1) != 0) {
                CRC >>= 1;
                CRC ^= POLYNOMIAL;
            } else {
                CRC >>= 1;
            }
        }
    }
    return CRC & 0xFFFF;
}
```

### Endianness
`DataTransferUtils.shortToBytes()` is used. We will extract `DataTransferUtils` to confirm byte order (usually Big-Endian for Java, but Bluetooth protocols often use Little-Endian).

## Legacy Fixed-Length Format (CommandHandle)
Commands initiated via `CommandHandle` use `BaseReqCmd.getData()`. 
These are **exactly 16 bytes** long.

| Offset | Length | Description |
|--------|--------|-------------|
| 0 | 1 byte | Command Key |
| 1 | 14 bytes | Payload Data |
| 15 | 1 byte | 8-bit Checksum |

**8-bit Checksum Algorithm**:
Simply the sum of bytes 0 through 14 modulo 256.
```java
int crc = 0;
for (int i = 0; i < 15; ++i) crc += data[i];
data[15] = (byte)(crc & 0xFF);
```
