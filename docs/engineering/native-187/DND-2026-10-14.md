## Implemented paths

NATIVE-159 now has an Android 10+ app-owned Do Not Disturb path. EN/LV/RU native commands use the existing canonical `halo_native_destination` tool, explicit foreground gate, mandatory approval and no-replay policy.

`NativeDndController` checks manually granted notification-policy access before activating or deactivating anything. It creates an explicit `AutomaticZenRule` with Halo's exact configuration Activity and condition URI. It never calls the global interruption-filter setter. This avoids treating Halo's companion-device integration as permission to change a global policy.

Only the matching managed rule is updated. A stale remembered ID cannot select an unrelated rule. A lost ID is recovered from Android's owned-rule inventory; multiple matches require manual review. Disabling without a matching rule creates nothing. A process-wide lock serializes creation and avoids duplicate rules across executor instances. No rule is resumed automatically on app startup or after permission grants.

Android 15+ rule-state readback may yield `ACKNOWLEDGED`; older Android versions retain dispatch-only truth. These receipts do not prove the phone is silent or that all other DND rules are disabled. [Android rule-state contract](https://developer.android.com/reference/android/app/NotificationManager#setAutomaticZenRuleState(java.lang.String,%20android.service.notification.Condition)), [rule readback](https://developer.android.com/reference/android/app/NotificationManager#getAutomaticZenRuleState(java.lang.String)).

`NativeDndSettingsActivity` is exported for Android's rule-configuration entry. It displays a localized explanation and links to manual special-access settings. It ignores caller extras and never changes a rule on launch. It uses the shared Halo theme and generated EN/LV/RU catalogue.

NATIVE-151 also has a manual Bluetooth-off settings destination with EN/LV/RU commands. The receipt explicitly says Halo did not toggle Bluetooth. The inventory's silent-toggle target remains Pending/restricted; the UI fallback is not counted as that capability being implemented.
