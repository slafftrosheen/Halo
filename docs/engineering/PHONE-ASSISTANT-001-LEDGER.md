## Wiring and constraints

Eight assistant tools are registered through ManualDependencyGraph → HostTools → HostToolRegistry → ToolRegistry; each has exact descriptor ownership, validated halo.assistant manifest/per-tool risk, bundled instructions, and local activation. Native app direct actions require the active Android assistant capability, API 29+, a fresh opaque token, and mandatory approval for dispatch. Model-authored extras/vendor commands are not accepted. Tokens expire at 30 seconds and are invalidated on dispatch, app invalidation, or session closure. Native app action labels and callback data are untrusted; dispatch is never reported as verified app success.

Public global accessibility actions (22 current constants) are filtered by API level and current getSystemActions evidence on API 30+. Fresh snapshot checks, package safety, durable approval, leases, journaling, and postconditions remain in the existing transaction pipeline. Long presses use node ACTION_LONG_CLICK, not synthetic coordinates; semantic swipe adaptation uses the existing scroll operation. Raw arbitrary gestures are deliberately excluded because they lack a reliable semantic target/verification contract.

Native assistant additions: explicit VoiceInteractor command negotiation, user confirmation/option UI, completion/abort/cancellation, API 26–28 assist context, API 29+ app direct actions, safe screenshot ownership, replaced/hidden session cleanup, and the real bounded RecognitionService endpoint. Recognition shares the existing microphone/foreground owner, selected STT model, and quality gate without publishing conversation events. It rejects unsupported external-audio/segmented sessions, reports busy ownership, wipes PCM, and cancels on service teardown. It does not change the selected language/model to satisfy an external caller.

Hotword DSP enrollment, secure-screen capture, global Wi-Fi/Bluetooth toggles restricted by Android, arbitrary shell/root commands, signature-only assistant powers, and undocumented OEM commands are not claimed. Mode-assistant-conversation eligibility checking documented for SDK 37.2 is not in the installed stable 37.0 SDK; no reflection or privileged mode assumption is introduced. Assistant audio uses USAGE_ASSISTANT on API 37, with a dedicated volume stream and observed volume receipts.

## Android 17 behavior audit and validation

The app now compiles and targets API 37; host-android compiles API 37, with minSdk 26 unchanged. Public APIs were checked against the installed stable android-37.0 SDK and official Android 17 documentation. Platform-specific actions remain guarded and settings/panels are resolved against actual installed handlers.

- Audio: API 37 assistant output uses USAGE_ASSISTANT and the assistant volume stream. A microphone foreground-service lease is retained while the native assistant interaction is visible, serializing start/cancel/hide so stale callbacks cannot cancel a successor or leak recording ownership. The privileged conversation mode is deliberately not enabled. RecognitionService uses the existing capture owner and selected STT pipeline, with a 15-second bound and explicit stop/cancel handling.
- Local network: ACCESS_LOCAL_NETWORK is declared and explicitly user-requestable on API 37. Permission changes refresh capability discovery. This is a runtime grant, not a promise that every network endpoint is reachable.
- Contacts: the existing READ_CONTACTS lookup had no manifest declaration; this is repaired with an explicit permission-screen grant. The existing lookup remains permission-gated and does not bypass Android 17 provider restrictions. The new public contact-picker session API is not used by this source harvest; no unrestricted contact-picker or contacts-database capability is advertised.
- Navigation/sharing: internal routes are exact allowlisted destinations; settings/panels depend on available intent handlers. App launches and text shares report dispatch, rather than confirmed external effects. Imported files retain the existing user-mediated SAF/URI grant boundary.
- Accessibility: every exposed global action uses API guards and, on API 30+, current service-advertised actions. Semantic long press uses ACTION_LONG_CLICK. Secure content, protected notifications/OTP, raw coordinates, hidden APIs, and root commands remain unavailable. Existing snapshot freshness/redaction and package policy still apply.
- Android 17 native-code/network restrictions are not bypassed: no arbitrary executable loading, certificate-validation override, or protected-message workaround is added. Real device checks are still needed for target-specific foreground audio, activity launch, local-network denial, and accessibility behavior.
